# 术语表

这一页用白话解释文档和源码里常见的词。读其他页面遇到看不懂的词时来这里查。每条只讲是什么，详细机制跟着链接去对应页面看。

## 设备与运行

| 术语 | 解释 |
|---|---|
| 宿主（host） | 相框上固定运行的底层固件，仓库是 `photopainter-host`。负责蓝牙、配对、应用管理和屏幕驱动，通过 USB 刷写。见[设备是怎么工作的](03-how-the-device-works.md)。 |
| 应用 / APP | 由宿主加载运行的小程序，是一个 ELF 文件，通过蓝牙单独安装。默认应用是 `photoframe`。 |
| 前台应用 | 当前正在运行的那个应用。同一时间只有一个，所有事件都发给它。 |
| ELF | 应用的可执行文件格式。宿主把它读进内存、重定位后直接调用，应用和宿主共用地址空间，不是独立进程。 |
| ABI | 宿主和应用之间的接口约定：有哪些事件、哪些宿主函数、结构体长什么样。版本写成“主版本.次版本”，现在是 2.3，次版本越高能用的功能越多。见[应用接口参考](05-app-api-reference.md)。 |
| 清单（manifest） | 应用 ELF 里一段固定格式的数据，写着应用 ID、名字、ABI 次版本、接受哪些输入、是否需要首屏。用 SDK 里的 `APP_MANIFEST*` 宏声明。 |
| 事件 | 宿主调用应用的方式。每种情况（启动、定时器到点、收到消息、即将卸载等）对应一个事件类型，如 `START`、`TIMER`、`STOP`。 |
| 回报结果 / `app_complete` | 应用在每次事件里必须调用一次的函数，告诉宿主这次处理成功还是失败。漏报或多报都算运行错误。 |
| `APP_READY` | 应用在 `START` 成功时带上的标志，表示“我已经准备好接收后续事件”。 |
| 首屏 | 应用在 `START` 里画的第一帧。声明了 `APP_REQUIRES_DISPLAY` 的应用必须画完首屏才算启动成功。 |
| generation | 应用的“第几次加载”计数，每加载一次加 1。事件、回复和通道会话都带着它，用来丢掉上一次加载留下的过期消息。 |
| 应用管理任务（App Manager） | 宿主里唯一调用应用、唯一修改应用目录的任务。所有操作在这里排队，一次只做一件。 |
| 故障空闲 | 宿主正常运行、但没有应用在运行的状态，通常在应用启动失败或运行出错后进入。这时仍然可以通过蓝牙管理相框，切换或激活应用后恢复。状态里的 `phase` 显示为 `fault`。 |
| 看门狗 | 宿主给每次应用调用设的计时器：普通事件 5 秒，画屏期间 650 秒。超时就重启整台设备。 |

## 应用槽与更新

| 术语 | 解释 |
|---|---|
| bank | 应用目录里的一个位置。宿主最多有 5 个 bank，每个已安装的应用固定占一个。 |
| 槽 / slot | 每个 bank 里存放安装包的 1 MiB 空间，一共两个：A 槽（编号 0）和 B 槽（编号 1）。 |
| 安装包 / `.pkg` | 写进槽里的文件：4 KiB 包头（版本号、长度、SHA-256、应用 ID）加上应用 ELF。用 `photopainter-host/tools/module.py` 打包。 |
| active | 当前确认可用、开机会加载的版本所在的槽。 |
| previous | 可以回退到的旧版本所在的槽。上传新包、或者启动保护回退后都会被清空。 |
| pending | 已经上传、还没激活的新版本所在的槽。上传总是写进不是 active 的那个槽。 |
| trial / 试运行 | 激活 pending 版本后、确认之前的状态。启动成功就确认，失败或中途重启就丢弃 pending、回到原版本。 |
| 激活（ACTIVATE） | 让宿主试运行 pending 版本的管理命令。 |
| 确认 | 试运行的版本启动成功后，宿主把它记为新的 active，原 active 变成 previous。 |
| 切换（SWITCH） | 把前台换成另一个已安装应用的 active 版本。功能键短按也是切换。 |
| 回退（ROLLBACK） | 有 pending 时丢弃它；没有 pending 时把 active 和 previous 互换。 |
| 删除（REMOVE） | 删除一个不在运行的应用的目录项。槽里的数据不擦除，下次分配时才覆盖。 |
| 启动保护 | 开机时防止坏版本反复崩溃的机制：启动前记一笔，启动成功后清掉；开机发现记录没清掉就回退到 previous。见[启动保护](03-how-the-device-works.md#启动保护)。 |
| USB 维护复位 | 电脑通过 USB 串口触发的复位，复位原因是 `ESP_RST_USB`。启动保护不把它当成启动失败。 |
| factory | Flash 上存放宿主固件的分区，偏移 `0x10000`。宿主只通过 USB 刷写这个分区，没有整机 OTA。 |
| NVS | ESP-IDF 提供的键值存储，放在 Flash 的专用分区里。宿主用 `nvs` 分区存配对关系和配置，用 `elf_state` 分区存应用目录和启动保护记录。 |
| PSRAM | 主板上额外的外部内存。宿主接收安装包、应用分配大块内存时都用它。 |

## 蓝牙与配对

| 术语 | 解释 |
|---|---|
| GATT | 蓝牙低功耗（BLE）上最常用的数据交换方式：设备公开一组“服务”和“特征”，客户端读写这些特征。浏览器的 Web Bluetooth 只能用 GATT。 |
| L2CAP CoC | 蓝牙低功耗里的一种面向连接的数据通道，可以连续传大块数据，比 GATT 快。ABI 2.2 起前台应用可以独占一条，目前只有 Mac 客户端使用。 |
| Web Bluetooth | 浏览器提供的蓝牙接口，网页插件用它在手机或电脑上直接连相框。 |
| 配对 v2 | 相框的配对方式：双方用 ECDH 交换密钥，相框屏幕显示一个六位码，你核对客户端上的码一致后短按功能键批准。之后每次连接都自动双向鉴权。见[蓝牙通信](06-bluetooth.md)。 |
| 主人 | 和相框完成配对的那一个客户端。同一时间只有一个主人；电脑后台和每个浏览器各算一个。见[上手使用](02-getting-started.md#一台相框只认一个主人)。 |
| 重置配对 | 长按功能键至少 8 秒后松开，相框撤销当前主人，回到可以重新配对的状态。已安装的应用和 Wi-Fi 配置保留。 |
| BondAuth | 配对之后每次连接时做的双向鉴权步骤，成功后才能执行管理命令和应用通信。 |
| 管理协议 | 宿主在蓝牙上提供的一组签名命令，包括查询状态、上传安装包、激活、切换、回退、删除，以及和应用交换消息。见[蓝牙通信](06-bluetooth.md#6-管理命令)。 |
| 通用消息 / CHANNEL | ABI 2.3 提供的应用通信方式：客户端和前台应用之间按“一条消息、一条回复”交换数据，不用关心底层是哪种蓝牙通道。在 GATT 上一条消息最大约 4 KiB。见[蓝牙通信](06-bluetooth.md)。 |
| COMMIT | 分块上传的最后一步，表示“数据传完了，请处理”。安装包上传和图片事务都有 COMMIT。 |
| 图片事务 | 客户端向 `photoframe` 发一张图的完整过程：`BEGIN`（声明长度和 SHA-256）→ 若干次数据块 → `COMMIT` → 等待回执。中途可以用 `QUERY` 查询、`CANCEL` 取消。 |
| 回执 | 应用对图片事务每一步的答复。只有与本次请求 ID、长度、SHA-256 都匹配、并且经过签名的完成回执，才证明这张图真的显示成功。 |
| PFI1 | `photoframe` 图片回执的格式名，每条回执固定 64 字节，以 ASCII `PFI1` 开头。 |
| `/health` | 相框在 Wi-Fi 上保留的唯一 HTTP 接口，返回 `{"device":"PhotoPainter","protocol":2,"transport":"paired-ble"}`，只用来探测在线。其他 HTTP 控制接口都返回 410。 |

## 电脑端与数据

| 术语 | 解释 |
|---|---|
| ai-quota-frame | 电脑端 Go 程序。`ai-quota-frame daemon` 是常驻后台，负责采集额度、渲染看板、推图；其他子命令用于蓝牙操作和诊断。见[电脑端、控制台与网页插件](07-clients.md)。 |
| CPA | CLIProxyAPI，一个代理多家 AI 服务的服务端程序。电脑后台和网页插件从它的管理接口读取额度和用量。 |
| CPM | CPA 的网页管理前端。网页插件以菜单项的形式出现在 CPM 里，并沿用 CPM 已保存的登录。 |
| CPM 网页插件 | 一个 CPA 插件，只负责托管页面。页面里的 WASM 生成画面，再用访问者设备的 Web Bluetooth 推图。 |
| WASM | WebAssembly。网页插件把电脑端同一套 Go 代码编译成 WASM，在浏览器里运行，所以两边生成的画面一致。 |
| macOS 控制台 | `photopainter-console`，Mac 上的图形界面。它通过本机 Unix socket 调用后台，和自动推图共用后台的设备队列。 |
| 主题 | 看板的样式：经典（`classic`）、街机（`arcade`）、波普（`pop`）、薄巧（`mint-skin`）。网页插件默认用薄巧，电脑后台默认用经典。 |

## 屏幕与图片

| 术语 | 解释 |
|---|---|
| Spectra 6 | 相框使用的彩色电子纸技术，能显示黑、白、红、黄、绿、蓝六种颜色。一次刷新约 20 秒，断电后画面保留。 |
| E6 | 源码里对这块 Spectra 6 面板驱动的叫法。 |
| 六色 PNG | 推给 `photoframe` 的图片格式：800×480、非隔行、完全不透明，每个像素只能是 `#000000`、`#ffffff`、`#ff0000`、`#ffff00`、`#00ff00`、`#0000ff` 之一，文件最大 5 MiB。 |
| 逻辑帧 | 应用交给宿主显示的一帧：800×480 个字节，从左上角逐行排列，每个字节是一个颜色编号（0–5）。旋转方向和硬件色码由宿主处理。 |
| 打包 | 宿主把逻辑帧旋转 180°、换成面板色码、两个像素合成一个字节，得到 192000 字节发给面板。 |
| 缓存 | 宿主给每个应用提供的一小块内存存储（每个应用最多 512 KiB，总共 1 MiB），切换应用后还在，重启后清空。`photoframe` 用它在切回来时恢复上一张图。 |
