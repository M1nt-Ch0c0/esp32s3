# 文档写作规范

这一页写给以后修改文档的人，也包括帮忙写文档的 AI。目标只有一个：读者打开任何一页，都能看懂它在讲什么，并且能照着做。

## 每页怎么组织

- 开头两三句话说清：这页讲什么、适合谁读、读完能做什么。
- 先讲是什么、为什么，再讲怎么做。原理和步骤分开写。
- 一个主题只在一个页面里详细讲。其他页面提到它时，用一句话加链接，不要复制粘贴。
- 能用表格、编号步骤、代码块、mermaid 图说清楚的，就别写成长段落。图要画真实的机制，不要画装饰图。

## 句子怎么写

- 用完整、平实的中文句子，一句话只说一件事。
- 术语第一次出现时解释一下，或者链接到[术语表](10-glossary.md)。命令、字段名、文件名保留原文，用反引号括起来。
- 用正面说法。写“图片必须是 800×480 的六色 PNG”，不要写“不能把非 800×480 的图片当作……”。
- 语气像懂行的同事给新人讲解，不用营销腔，也不用感叹号。

## 只写现在

文档描述的是系统现在的样子，不是开发日记。下面这些都不要出现在正文里：

| 不要写 | 原因 |
|---|---|
| “已不再是 X，而是 Y”“当时……现已……” | 读者只关心现在是什么，旧做法放进 Git 历史 |
| “本轮”“今晚”“早上”“尚未实机验证”这类时间和过程词 | 过几天就过期，而且会误导 |
| 一长串免责声明，比如“不能据此认定……”“不代表……” | 把正文淹没了。设计上的限制写进[版本与已知限制](09-versions-and-limits.md) |
| 提交 SHA、文件摘要、备份路径、某天几点几分的观测 | 属于发布记录，不是说明文档 |
| 个人电脑路径、IP、密钥 | 隐私和安全问题 |

性能数字可以写，但要写成大约多少，并说明条件，例如“手机网页 GATT 传 66 KiB 约 8 秒”。

## 以代码为准

写进文档的行为、字段、数值、命令，都要在源码里核对过。核对不了的就不写。改了接口，就在同一次改动里更新对应的文档。

## 写产品，不写某一台设备

文档描述的是产品：它的设计、行为、用法和限制，对每一台相框都成立。下面这些不写进文档：

- 某台设备的序列号、设备 ID、当前装了哪个版本、现在的主人是谁；
- 开发或使用过程中遇到的具体事件，比如“某次断电后退回了旧版本”；
- 某台电脑、某块网卡、某部手机上的个别现象；
- 测试做到哪一步、谁验证过什么。

设计层面的限制（比如“启动保护不区分复位原因”）写成产品行为，放在对应的原理页，并在[版本与已知限制](09-versions-and-limits.md)里列一行。示例里用通用的值，比如设备 ID `001122334455`、版本 v1、v2。

版本号和已知限制只写在[版本与已知限制](09-versions-and-limits.md)，更新时直接改成最新情况。
