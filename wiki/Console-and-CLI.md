# 控制台与 CLI 能力

[返回首页](Home.md) · [维护](Operations.md) · [当前交付状态](Status-and-Evidence.md)

[photopainter-console](https://github.com/M1nt-Ch0c0/photopainter-console) 是独立 macOS SwiftUI 操作界面。Go 后台仍在 ai-quota-frame；界面通过同一受权限保护的 Unix socket 请求后台，设备操作与自动推图共用串行队列。原理、教程和 SDK 学习内容已移到本 Wiki，GUI 不再提供“工作原理”页面。

界面功能是否可用，由当前后台能力、已鉴权设备状态和前置条件共同决定。失败、未知或缺少遥测必须明确显示，不能用占位数值冒充设备数据。

当前界面版本为0.4.0 / build 5，按八个页面组织。完整action字典与IPC字段见 [控制台README](https://github.com/M1nt-Ch0c0/photopainter-console#操作界面)，实际安装/执行证据见状态页。

## 操作分组

| 控制台区域 | 对应能力 | 条件与边界 |
|---|---|---|
| 运行总览 | 后台启动/停止/重启，自动推图暂停/恢复、立即采集、进度、实际GATT/CoC、耗时和速率 | 服务启停使用固定LaunchAgent流程；暂停只阻止后续推送，停服不等同取消已提交的实体显示 |
| 设备与应用 | 签名完整状态、目录/槽/版本、包检查、安装、激活、切换、回滚、删除、结束试运行、同版本备用槽重建 | 安装写备用槽；修改前由后台重新读取状态；不重放不确定管理命令 |
| 连接与发现 | BLE扫描、设备info、设备绑定/解绑 | 扫描记录未经认证；info与可授权目标需完成既有鉴权 |
| 图片推送 | 选择PNG、格式检查、单次推图 | 800×480、非隔行、不透明精确六色；最终回执才表示显示完成 |
| 应用通信 | app-read / app-write，按应用与特征索引读写 | 当前前台APP、有效generation/revision、ABI 2.1小消息长度限制 |
| Wi-Fi配置 | 设备HTTP配置与本地SD/JSON文件的列表、设置、增删、排序、备份/更新 | HTTP模式需要可达私网与设备SD；本地模式选择配置文件，不假装已写入设备；按规则重启/重新插卡生效 |
| 诊断 | 完整安全状态、最近事件、操作结果、本机doctor、串口probe、能力与导出 | 串口probe可能复位设备，须停竞争并明确提示；不读取普通服务日志或显示凭据 |
| USB维护 | 串口枚举、镜像检查、完整Flash备份、宿主更新、完整恢复、首次provision | 精确核对设备；独占维护；先备份校验再写入；不可与BLE/推图并发 |
| 应用包工具 | ELF检查与打包 | 本机文件操作；不把普通firmware bin当作APP包；打包入口位于设备与应用页 |

CLI参考：ai-quota-frame 的 `cmd/ai-quota-frame/ble.go`、`console.go`，宿主 `tools/module.py`、Wi-Fi工具及 `tools/doctor.py`。后台的具体IPC字段和能力列表以当前代码为准，不把相似名称当作相同操作。

## 可观测内容

- 电脑后台：进程开始时间、自动更新状态、主题、采集时间/下次计划、源端新鲜度、操作队列、最近安全事件。
- 图片：实际选择的通道、已发送/总字节、发送阶段耗时和速率、等待显示/查询回执/完成/未知状态、最近确认画面。
- 设备：阶段、运行APP与槽、发布版本、ABI主/次版本、加载/就绪/确认、generation、uptime、reset_reason、内部RAM/PSRAM与缓存。
- 应用目录：bank、active/previous/pending/trial、槽版本与按键候选资格。
- 通信：BLE服务与特征、CoC协议/注册状态、鉴权后设备信息；完整原始状态补充结构化界面未单独展示的现有字段。

设备没有上报的电池电压、剩余电量、PMIC关机原因等不能推算出来。reset_reason说明一次启动的复位类别，不能单独证明低电、USB故障或具体代码根因。

## 操作结果的含义

1. 扫描看见设备，只证明广播被收到。
2. GATT/CoC能力存在，只证明该接口可协商；实际通道由本轮发送器报告。
3. 发送进度到100%只说明数据已交给传输；CoC计时不包括全部连接和刷屏。
4. 包暂存成功不等于已激活；APP ready不等于本次图片已经显示。
5. 可信物理完成必须有匹配请求ID、长度、SHA和complete/OK的业务回执。

COMMIT结果不确定时，后台保留身份并查询原回执。APP切换、重启或缺失回执会使结果未知，禁止自动重画。手动操作也使用同一队列和规则。

## USB维护与首次初始化

宿主更新只写已有布局的factory `0x10000`。完整恢复会替换备份中的配置、目录和应用数据，界面必须明确确认并保留当前恢复点；不能把恢复当作普通APP安装。

首次配置分为 `provision-generate` 和 `usb-provision`：前者从已有私有配置路径生成受保护NVS镜像，不写设备；后者先确认凭据变化影响，再确认备份后写入。GUI不读取私有配置正文。已经配置好的设备通常使用保留配置的宿主更新；首次布局迁移仍需核对实际分区。串口 `serial-diagnose` 也可能复位设备。

工具链安装、源码编译及任意esptool底层命令不等于设备运行能力；控制台使用固定维护工作流，不开放任意shell执行。准确参数和限制以宿主工具及后台capabilities返回为准。

## 开发与发布

SwiftUI源码、PRODUCT、构建脚本属于photopainter-console；Go采集、渲染、设备队列、BLE实现及IPC属于ai-quota-frame。二者配套构建部署，但各自提交，凭据和设备备份不进任一仓库。当前版本、实际已部署操作和局限见 [状态页](Status-and-Evidence.md)。
