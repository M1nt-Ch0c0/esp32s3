# 鉴权与安全边界

[返回首页](Home.md) · [配对协议](BLE-Protocol.md)

**配对 v2 尚未实机验证。** 源码测试、签名检查和模拟按键不等于真实设备上的物理同意、重启持久化或完成显示。

## 配对和撤权

设备不再接受用户配置的固定推图令牌。P-256 双方承诺/揭示和 HKDF 产生候选关系；计算同一组六位码，客户端候选先持久化，设备显示完成后由 GPIO4 功能键短按批准。NVS 提交成功才建立 owner。

本机保存关系后每次重连使用新 Challenge 和 BondAuth。浏览器 CryptoKey 不可导出，IndexedDB 必须 strict durability；原生使用私有文件、持久同步和每设备跨进程锁。候选不能覆盖其他候选，迟到确认不能复活已经移除的关系。失败/未知的取消回复不能视为解绑或批准成功。

长按功能键八秒并松开能在刷新中提出撤权，立即关闭新工作的入口；旧刷新和借用任务有界结束后才清除持久关系。不存在远程替换 owner 的接口。旧固定 token 的 BLE op 1 拒绝，旧 HTTP 控制入口返回 410，不能绕过物理重置。

## 凭据边界

- CPM 管理密钥只用于受信站点的数据源请求，不传给设备或写入浏览器持久存储。
- OAuth/管理/Wi-Fi 凭据、Flash/NVS/SD 备份不入库，不进入聊天或普通诊断输出。
- xAI 账号 subject 由受管理鉴权保护的窄接口投影；浏览器不下载完整 OAuth 文件。
- 配对密钥不进入服务器或 APP；APP 是共享地址空间的受信任原生 ELF，这不是恶意代码沙箱。
- 固定测试向量是公开的合成测试材料，不能用作设备凭据。

配对 v2 是应用层认证，不是操作系统 SMP bond。业务签名提供完整性与防重放，不声称图片内容已加密。设备重置保留应用和画面缓存，因此也不是清除恶意应用或数据的出厂擦除。

## 业务结果

只有匹配请求 ID、长度、SHA、接收字节数的签名完成回执才证明本次物理刷新与 POWER_OFF 等待完成。丢失结果时保留身份、只查询原请求；BID/代次变化或回执丢失时停止自动重画。浏览器跨标签页使用会话锁，缺少该能力时不能静默并发。

电脑后台保持主动出站和受保护 Unix socket，设备不做公网端口映射。遵循系统蓝牙权限，不绕过 TCC。宿主写入前需核对精确设备和完整备份；整块 NVS 恢复会覆盖配对，必须与仅写 factory 的更新区分。
