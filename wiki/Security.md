# 安全与兼容边界

[返回首页](Home.md)

## APP 是受信任原生代码

ELF 共享宿主地址空间，没有进程隔离、MMU 沙箱或恶意代码防护。manifest 与导入白名单用于结构/兼容性和生命周期约束，不能证明任意 APP 安全。只安装可信来源，不能把包 SHA-256 当作者签名。

APP 不保存设备令牌、Wi-Fi 密码或额度管理凭据，不自行绕过 SDK 操作无线栈和硬件。新业务需通用服务时先做接口审计与最小扩展提案。

## BLE 的威胁模型

当前 HMAC 挑战响应和会话序列号保护身份、完整性与重放。令牌不在 BLE 上传输；捕获的证明仍可用于离线猜测弱令牌，所以必须用随机强令牌。

BLE 链路不加密，发现元数据、图片、应用包和状态可被旁观者观察。无线拒绝服务、强制断开和实时中继不在该机制解决范围。若业务需要内容保密，必须单独设计加密或安全配对方案，不能仅将 HMAC 改名为“加密”。

稳定设备 ID 允许近距离跟踪，SSID 截断哈希不能阻止常见名称的字典猜测。广播不能携带令牌、Wi-Fi 密码或源端凭据。未经鉴权只能读取公开发现与完成认证所需的 bootstrap 信息。

应用直接特征通知不带 HMAC，成功凭据应通过签名读核对；客户端不凭广播 IP 或未签名通知作授权决定。

## 凭据、日志与主机

设备令牌与源端管理/OAuth密钥独立。真实配置、Flash/NVS/SD 备份和令牌日志不打开、打印、提交或粘贴；可信启动器可私下加载配置。参数、截图、测试输出与 PR 示例只用占位符。

设备 HTTP 不跟随代理和重定向，不做公网端口映射。电脑端只主动访问数据源/设备，不恢复旧健康监听端口；Windows 看门狗只看进程存在。macOS 按系统蓝牙权限运行，不绕过 TCC。

## 兼容性不是安全保证

版本拒绝应在执行前发生。未知 ABI、能力或非法包不能通过手工改头“修复”。安装只写备用槽，试运行先记录日志，失败有界回退；回退不能证明某 APP 来自可信作者。

重新连接、APP 切出或设备复位会改变数据和回执生命周期。接收端要界定去重范围，客户端遇到未知结果停止自动重画，不能以牺牲显示安全来提高重试成功率。
